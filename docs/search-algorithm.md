# Алгоритм поиска документов

Как `fetch_document()` находит НПА на publication.pravo.gov.ru и как
`fetch_its()` находит справочники ИТС на burondt.ru. Поведение API портала —
[`api-reference.md`](api-reference.md); ход проектирования —
[`history/stage1-plan.md`](history/stage1-plan.md).

## НПА: входные данные

`Query` содержит либо `eo_number`, либо номер, дату подписания и орган
(название или GUID); без них результат — `invalid_input`. Полное официальное
название разбирается в реквизиты функцией `parse_citation()`: поддерживаются
месяц прописью, сокращённые названия органов («Минприроды России») и хвост
«(в ред. …)» — реквизиты берутся из исходного акта.

## НПА: шаги поиска (`search.search_document`)

1. **Известен `eoNumber`** — карточка запрашивается напрямую
   (`/api/Document?eoNumber=…`).
2. **Органы-кандидаты.** Название органа ищется в локальном кэше справочника
   органов (`AuthorityCache.resolve`): сначала точное совпадение
   нормализованного названия, затем по подстроке. Результат — 0, 1 или
   несколько GUID; дальше все случаи обрабатываются одной схемой.
   Нормализация названия: «ё» → «е», регистр, кавычки, пробелы, сокращения
   («минфин», «минприроды», «роснедра»). Записи кэша только добавляются и
   обновляются, поэтому органы, пропавшие из справочника портала, остаются
   доступны.
3. **Нормализация номера** — с обеих сторон сравнения: тире и дефисы → `-`,
   без пробелов и знака «№», сравнение без учёта регистра.
4. **Точный номер** (`NumberSearchType=0`, все страницы ответа):
   - один кандидат — запрос с `SignatoryAuthorityId`, сервер сам отбирает
     документы органа;
   - несколько или ноль — запрос без органа; затем отбор по дате, загрузка
     карточек оставшихся документов и отбор по полному списку подписантов (в
     списке есть только основной подписант, а совместный документ может быть
     подписан кандидатом не основным).
5. **Отбор на клиенте**: точная дата подписания (сервер даты не фильтрует, а
   номера повторяются по годам), удаление повторов по `eoNumber` (совместный
   документ находится через каждого подписанта), тип документа, если задан.
6. **Запасной поиск по цифровой части номера**, если после шагов 4–5 ничего
   не осталось. Цифровая часть — цифры до первого нецифрового знака (у номера
   не с цифры её нет, и поиск не выполняется). Запрос `NumberSearchType=1`
   («начинается с»), на клиенте — проверка границы: после цифровой части идёт
   нецифровой знак или конец номера («310» не совпадает с «3100»). Без
   единственного кандидата поиск выполняется, только если цифровая часть не
   короче трёх цифр (иначе выборка слишком велика). Найденное помечается
   `match_type=digits_only`.
7. **Итог** (`search.decide`): один документ — `found`, несколько —
   `ambiguous` со списком кандидатов (автовыбора нет), ноль — `not_found`
   или `out_of_range`.
8. **Диагностика `not_found`**: документы с тем же номером и датой у органов
   вне списка кандидатов — признак того, что орган определён неверно
   (переименование, неточное название). При одном кандидате для этого делается
   отдельный запрос без органа. Сбой диагностики не меняет статус.

`out_of_range` возвращается только после неудачного поиска, если дата
подписания раньше `COVERAGE_START` (08.11.2011): граница охвата портала идёт
по дате публикации, и документ, подписанный раньше, но опубликованный позже,
может быть найден. Для `out_of_range` пробуется поиск в ips.pravo.gov.ru (см.
[`ips-pravo-coverage.md`](ips-pravo-coverage.md)).

## НПА: после поиска (`service.fetch_document`)

1. Найденные карточки сохраняются в БД (`documents`, `document_signatories`).
2. PDF скачивается (`/file/pdf?eoNumber=…`), если его ещё нет на диске с тем же
   sha256, и проверяется: размер по `Content-Length`, сигнатура `%PDF`,
   маркер `%%EOF`, чтение числа страниц.
3. Текст: действующая редакция из EBPI (см.
   [`ebpi-coverage.md`](ebpi-coverage.md)), иначе — текстовый слой PDF, если
   PDF не скан. Сканы распознаёт npa-ocr (см.
   [`ocr-integration.md`](ocr-integration.md)).

## Контракт результата НПА

| `status` | Значение |
|---|---|
| `found` | Один документ; при скачивании `pdf_path` заполнен |
| `found_text_only` | Документ старше границы охвата найден в ips.pravo.gov.ru: есть текст, PDF нет |
| `not_found` | Среди кандидатов органа ничего нет; `diagnostics` — находки у других органов |
| `ambiguous` | Несколько документов в `candidates` (или `ips_candidates`) |
| `out_of_range` | Дата раньше границы охвата, и запасной поиск не дал одного документа |
| `invalid_input` | Нет номера, даты или органа либо название не разобрано |
| `network_error` | Сбой сети после повторов |
| `integrity_error` | Скачанный PDF не прошёл проверку |

При `network_error` и `integrity_error` найденный `eo_number` возвращается,
чтобы повтор шёл сразу по нему. Пустые `diagnostics` при `not_found` означают,
что документа с этим точным номером нет ни у одного органа; диагностика по
цифровой части номера не выполняется.

## ИТС: поиск на burondt.ru

У справочников ИТС нет `eoNumber`, и на burondt.ru нет поиска по реквизитам.
Карточки лежат по последовательным `UrlId` в диапазоне, общем с ГОСТами и
документами технических рабочих групп.

1. **Обход диапазона** (`ItsCache.refresh`): карточки `NDTDocsDetail.php?UrlId=N`
   обходятся подряд с `UrlId=10`; сохраняются только те, чьё «Обозначение»
   начинается с «ИТС». Внутри диапазона бывают пропуски; конец диапазона —
   серия из 40 пустых карточек подряд, и он каждый раз определяется заново
   (архив пополняется). Обход продолжается от сохранённой границы и может
   выполняться частями (`max_requests`).
2. **Файлы карточки**: справочник и приказ Росстандарта об утверждении
   (иногда приказ об отмене, иногда парная карточка «в формате Word»). Роль
   файла определяется по подписи, при её отсутствии — по размеру.
3. **Поиск по запросу** (`ItsCache.resolve`):
   - обозначение («ИТС 28-2021», в том числе внутри фразы с темой) — точное
     совпадение, затем по подстроке, затем по подписи файла приказа (в
     «Обозначении» год бывает не указан);
   - год («2021») — все справочники года (по суффиксу обозначения или дате
     приказа);
   - номер без года («ИТС 53») — все версии номера, новые первыми; номер
     сравнивается целиком («53» не совпадает с «530»).
4. **Скачивание** (`fetch_its`): файлы карточки и, если есть, Word-версия
   справочника; для PDF, который не скан, — .docx из текстового слоя.

Номер и дата приказа берутся из подписи файла на карточке и могут не
совпадать с самим приказом, поэтому в результате они помечены как
непроверенные (`order_meta_verified=false`).

## Хранение

Одна база SQLite `data/npa.db`, раздельные таблицы для НПА и ИТС (у них разная
идентификация и разное число файлов на документ):

- **НПА:** `authorities`, `documents`, `document_signatories`,
  `document_files`, `document_ebpi`, `document_relations`, `ips_documents`;
- **ИТС:** `its_documents`, `its_files`, `its_document_files`,
  `its_crawl_state`.
