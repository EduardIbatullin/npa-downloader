# Справочник по поисковому API ips.pravo.gov.ru

ИПС «Законодательство России» (`ips.pravo.gov.ru`) находит федеральные акты по
номеру и дате без `eoNumber` и отдаёт текст действующей редакции. Проект
использует его для документов старше границы охвата publication.pravo.gov.ru
(`models.COVERAGE_START`, 8 ноября 2011): у них нет `eoNumber`, и основной
поиск их не находит.

Официальной документации у API нет: сведения ниже получены разбором кода сайта
(React-приложение, `main.js`) и запросами к нему. Клиент —
`src/npa_pipeline/ips_pravo.py`. Авторизация не нужна, `robots.txt` на хосте нет.

## Место в поиске

API подключено только как запасной путь: когда основной поиск на
publication.pravo.gov.ru закончился `out_of_range`. Для документов в пределах
охвата основной API надёжнее: он документирован, отдаёт реквизиты отдельными
полями и встроен во весь алгоритм поиска (см.
[`search-algorithm.md`](search-algorithm.md)).

## Цепочка «найти → карточка → текст»

### 1. Поиск: `POST /api/ips/legislation/search.json`

Тело — `application/x-www-form-urlencoded`:

```
searchType=attrSearch&number_eq=7-ФЗ&date=10.01.2002,10.01.2002&bpas=c000000000&page=1
```

| Параметр | Значение |
|---|---|
| `searchType` | `attrSearch` — поиск по реквизитам (`smartSearch`, `hybridSearch` не проверялись) |
| `number_eq` | Номер, точное совпадение (`number` — нечёткое) |
| `date` | Диапазон `ДД.ММ.ГГГГ,ДД.ММ.ГГГГ` (ISO-формат не работает) |
| `bpas` | База: `c000000000` («Федеральное законодательство», с 28.07.1952) |
| `organ` | Орган-подписант строкой из `bpa-organ.json` (см. «Ограничения») |
| `page` | Страница результатов |

Ответ:

```json
{
  "docs": [{
    "state": "Действует с изменениями",
    "name": "Об охране окружающей среды",
    "adoption": "Федеральный закон от 10.01.2002 № 7-ФЗ",
    "docdate": "10.01.2002",
    "nd": "1000000000102074303",
    "image": null,
    "publications": ["\"Российская газета\" от 12.01.2002 г.", "..."]
  }],
  "page": 1
}
```

- `nd` — идентификатор документа в ИПС (не `eoNumber`). Если документ есть на
  publication.pravo.gov.ru, `image` содержит ссылку на него.
- `adoption` — реквизиты одной строкой.
- `state` — статус документа текстом.

Список баз отдаёт `GET /api/ips/legislation/bpas.json`; известна одна.

### 2. Карточка: `GET /api/ips/legislation/document_card.json?nd=<nd>&bpa=c000000000`

Вместо `nd` можно передать `pubnumber=<eoNumber>`. Главное в карточке —
`redactions[]`:

```json
{
  "id": 99,
  "actual": true,
  "date": "01.09.2026",
  "status": "актуальная",
  "onumber": "304-ФЗ", "odate": "31.07.2025",
  "refadoption": "Федеральный закон от 31.07.2025 № 304-ФЗ",
  "refnd": "1000000000607599126",
  "comment": "ст. 1, 5, 23, ..."
}
```

- `id` — ключ редакции (`rdk`) для запроса текста.
- `status` — `"актуальная"` (действующая, обычно одна), `"недействующая"`,
  `"не вступившая в силу"` (будущие редакции).
- `refnd` — `nd` акта, которым введена редакция.

`select_latest_redaction()` выбирает редакцию по `status`: `"актуальная"` с
наибольшим `id`, иначе наибольший `id` среди уже вступивших в силу. Поле
`actual` не используется: его надёжность не проверена, а у EBPI аналогичное
поле ненадёжно.

### 3. Текст: `GET /api/ips/legislation/documenttext?nd=<nd>&bpa=c000000000&rdk=<id>&completed=true`

Параметр `completed=true` обязателен: без него API отвечает `200 OK` с пустым
`doctext`. Ответ — `{"doctext": "<!DOCTYPE html>…", "rdk": …}`: HTML в том же
стиле Word-экспорта и с теми же классами абзацев, что redtext EBPI, поэтому
.docx собирается тем же конвертером `convert_redtext_to_docx()` (см.
[`ebpi-coverage.md`](ebpi-coverage.md), «Формат текста»).

### Другие эндпоинты

Найдены в коде сайта, но не проверялись: `document_refs.json` (связи
документов), `search_prompt.json` и `common-search.json` (подсказки и
текстовый поиск), справочники фильтров `bpa-doctype.json`, `bpa-region.json`,
`bpa-keyword.json`, `bpa-edition.json`, приложения `document_file` и
`document_supplements.json`.

## Результат поиска

| Найдено в ИПС | Статус `Result` | Поля |
|---|---|---|
| Ровно один документ с текстом | `found_text_only` | `ips_nd`, `ips_docx_path`, `ips_state`, `ips_adoption`; `pdf_path` всегда `None` |
| Несколько | `ambiguous` | `ips_candidates` — словари `{"nd", "adoption", "docdate", "state", "publications"}`; `candidates` пуст |
| Ничего | `out_of_range` | — |

`found_text_only` — отдельный статус, а не `found` без PDF: при `found`
`pdf_path` заполнен всегда, и код, разбирающий статус, не должен об этом
догадываться. Кандидаты ИПС не `DocItem`, так как у них нет `eoNumber`.

Найденные документы записываются в таблицу `ips_documents` (`nd`, реквизиты,
статус, путь к .docx; без внешнего ключа на `documents`). Повторный поиск того же
документа берёт готовый .docx, а веб-приложение отдаёт его по
`GET /api/docx/{nd}`.

## Ограничения

- API не документировано и может измениться; любой сбой или неожиданный ответ
  трактуется как «документа нет».
- Фильтр `organ` не используется: значение, под которым хранится орган
  федеральных законов, не установлено (запрос с `organ=Президент` ничего не
  находит). Номер с точной датой обычно дают однозначный результат.
- Статус отменённого документа (значение `state` у утратившего силу акта) не
  проверен.
- Конвертация проверена на тексте без таблиц; совпадение разметки таблиц с
  EBPI не проверено.
- Однозначность поиска по номеру с точной датой для номеров, повторяющихся
  каждый год (например, «7-ФЗ»), проверена выборочно.
