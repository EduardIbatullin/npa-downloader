# Справочник источников для этапа 2 (статус документа и история изменений)

Факты получены эмпирическим тестированием (прямые запросы к живым сайтам), не из документации — у большинства источников ниже открытой документации вообще нет. Дата проверки: 2026-09-26.

## `ips.pravo.gov.ru` — основной источник, но узкое покрытие

`GET http://ips.pravo.gov.ru/api/ips/legislation/document_card.json?pubnumber=<eoNumber>` — принимает тот же `eoNumber`, что и `publication.pravo.gov.ru` (этап 1), прямая связка без резолвинга.

**Этот же хост умеет находить документ и без `eoNumber`** — отдельный поисковый
эндпоинт (`search.json`), найден позже и описан отдельно в
[`docs/ips-pravo-coverage.md`](ips-pravo-coverage.md): решает задачу поиска
документов старше границы охвата `publication.pravo.gov.ru` (до 2011 года, база
покрывает с 1952 года), которую `document_card.json` не решает (ему всё равно
нужен готовый `eoNumber`). Покрывает ли `search.json` те же «5 органов» или шире —
не проверено, проверен только 1 документ (федеральный закон 2002 года).

**Покрытие подтверждено систематическим тестом на 13 комбинациях орган×тип.** Реально покрыты только 5 высших федеральных органов:
- Президент РФ,
- Правительство РФ,
- Государственная Дума ФС РФ,
- Совет Федерации ФС РФ,
- Конституционный Суд РФ.

**Не покрыты (проверено, все дают 404):** любые ведомственные приказы федеральных министерств/служб/агентств (Минфин, ФНС, МВД, Роснедра, Минприроды — 5 разных примеров), любые акты любого уровня субъектов РФ (Правительство Санкт-Петербурга, Губернатор Санкт-Петербурга), Постановление Роспотребнадзора (федеральная служба, не министерство). Важно: непокрытие определяется **органом**, а не типом документа — Постановление/Распоряжение встречаются и в покрытом, и в непокрытом списке.

**Ответ при покрытии:**
- `state` (верхний уровень) — статус всего документа текстом: `"Действует без изменений"` / `"Действует с изменениями"` / `"Утратил силу"`.
- `redactions[]` — полная история редакций, каждая запись: `date`, `onumber` (номер изменяющего акта), `odate`, `refadoption` (полная цитата), `comment` (какая статья/пункт менялись), `status`, `actual` (bool — это ли текущая редакция).
- Поля `minustdate`/`minustnum` (верхний уровень) — по названию должны быть датой/номером отменяющего акта, но на реальном подтверждённо отменённом документе оказались `null`. **Не использовать эти поля** — реальный механизм отмены: взять редакцию с `actual: true`, её `state`, и если это `"Утратил силу"` — её собственные `onumber`/`odate`/`refadoption` и есть ответ «чем отменён».
- 404 → документ не покрыт, переходить к `docs.cntd.ru`.

## `docs.cntd.ru` — лучший источник для всего остального (рекомендуется как основной fallback)

Электронный фонд правовой и нормативно-технической информации (АО «Кодекс»/Техэксперт).

**Доступ:** первый запрос к сайту делает redirect через SSO-бутстрап (`auth.kodeks.ru`) — нужно один раз пройти его с сохранением cookies (`-L` + cookie jar), дальше сессия работает.

**Поиск:** `GET https://docs.cntd.ru/search?q=<текст>` — рендерится на сервере (Vue/Nuxt SSR), в HTML сразу есть настоящие ссылки `<a href="/document/<ID>">`, JS для получения результатов не нужен. Текстовый запрос вида `"Приказ <орган> <номер> <дата>"` работает.

**Карточка документа:** `GET https://docs.cntd.ru/document/<ID>` содержит:
- явный статус в тексте — `"Действующий"` / `"Недействующий"`;
- в заголовке — `"(с изменениями на <дата>)"` с датой последней известной правки;
- если отменён — явный блок: `"Утратил силу с <дата вступления отмены в силу> на основании <орган> от <дата акта> № <номер>"` — обратите внимание, здесь **две разные даты** (дата самого отменяющего акта и дата, с которой отмена реально действует) — обе присутствуют явно;
- блок **«Информация об изменяющих документах»** — список всех правок, и для каждой в скобках указан **`eoNumber` с publication.pravo.gov.ru** (`N 0001YYYYMMDDNNNN`) — то есть каждая правка сразу даёт готовый ключ для этапа 1, резолвинг не нужен.

**Проверено на 3 реальных случаях (все совпали с независимо подтверждённой правдой — но независимая правда получена из разных источников, не только из `ips.pravo.gov.ru`; прямая сверка cntd vs ips сделана только на одном из этих трёх, см. `stage2-plan.md`, «Массовая сверка»):**
- Приказ Минприроды №434 от 03.07.2019 — «Действующий», 2 правки (10.12.2020 №1042, 26.04.2022 №304), обе с верными `eoNumber`.
- Приказ Минприроды №214 от 30.03.2021 — «Недействующий», «Утратил силу с 18.10.2025 на основании приказа Минприроды России от 13.08.2025 № 434».
- **Постановление Правительства Санкт-Петербурга №719 от 08.09.2026** — «Действующий», `eoNumber` совпал точно. Подтверждает покрытие региональных актов, не только федеральных ведомств.

**Собственный `eoNumber` документа встроен в структурированный блок на странице** (`publications:[...]`, `registrations:[{date, number, department}]` — часть Nuxt/Vue hydration-данных, не просто проза, парсится надёжнее регуляркой по тексту). Подтверждено на простых документах (2019, 2021, 2026 года). **Но не универсально**: на объёмном документе с длинной историей правок (закон, изменённый 200+ раз с 2012 года) поле `publications` содержало только даты публикации, без `N 0001...` — то есть сопоставление кандидатов по `eoNumber` работает не всегда, нужен резервный путь сравнения по номеру+дате+органу.

**Критическая находка — `robots.txt` явно запрещает автоматический поиск:**
```
Disallow: /*?
Disallow: /search?
Disallow: /api
```
Эндпоинт `/search?q=...`, на котором строится резолвинг документа по реквизитам, — прямо запрещён для ботов. Страницы `/document/<ID>` не запрещены (можно читать, если ID известен из другого источника). Тот же вопрос обнаружился у `publication.pravo.gov.ru` (`/File` запрещён, используется в этапе 1) — это единый вопрос для всего проекта, не частность `docs.cntd.ru`. Управленческий вопрос, не техническая деталь — см. `stage2-plan.md`, раздел «Блокирующий вопрос».

**Проверенные обходные пути к ID без собственного поиска `docs.cntd.ru` — не существуют.** Страницы `bazanpa.ru`/`rulaws.ru` не содержат ссылок на `docs.cntd.ru` (проверено на реальных примерах — 0 совпадений). Собственный `Sitemap` из `robots.txt` (`documents_sitemap.xml` → под-файлы вроде `documents_1_sitemap.xml`, ~10 000 URL каждый) — проверен, содержит только `<loc>`+`<lastmod>`+`<priority>`, без названий/номеров, как и у Гаранта — непригоден для сопоставления по реквизитам. Отдельного текста пользовательского соглашения (кроме общей копирайт-строки в подвале сайта) не нашёл — вопрос решается только напрямую с АО «Кодекс».

**Техническая защита от программного доступа — проверена, практически отсутствует.** Заголовки ответа не содержат следов известных анти-бот вендоров (Cloudflare, DDoS-Guard, Akamai, Imperva, PerimeterX, DataDome, Incapsula) — бэкенд обычный `X-Powered-By: Express`. Единственный «шлюз» — SSO-сессия (`auth.kodeks.ru`), и её поведение нелогично: с обычным браузерным User-Agent, без сохранённых cookies — 5 из 5 запросов дали `302` на SSO-бутстрап; **с пустым User-Agent — 10 из 10 запросов сразу дали `200 OK`, без какой-либо сессии или проверки вообще**. То есть шлюз ориентирован на «похоже на браузер» (вероятно, это аналитика/персонализация, не защита), а не похожий на скрипт запрос проходит без всякой проверки. Rate limiting не сработал на 10 быстрых запросах подряд — все `200`. **Вывод: технического барьера, требующего обхода, нет — есть только декларативный (`robots.txt`), см. ниже разбор рисков.** Не проверено: поведение при нескольких совпадениях в поиске.

### Разбор рисков работы без разрешения «Кодекса» (не юридическая консультация)

Раз технической защиты нет, вопрос «получится ли» не стоит — вопрос только в допустимости. Категории риска:
- **Технический** — низкий сейчас, но не гарантирован: защиту могут включить в любой момент без предупреждения, тогда инструмент молча перестанет работать.
- **Гражданско-правовой** — сами тексты законов копирайтом не защищены (ст. 1259 ГК РФ прямо исключает официальные документы госорганов), но структурированная разметка «Кодекса» (статус, «Информация об изменяющих документах» и т.п.) — их собственная база данных, на которую есть отдельное смежное право (ст. 1260 ГК РФ), независимо от копирайта на содержимое. Отдельного текста пользовательского соглашения не нашли — если он есть и запрещает автоматический сбор, его нарушение — потенциальное основание претензии даже без подписанного договора. Вероятность реального иска для некоммерческого внутреннего инструмента с невысоким объёмом — низкая, но не нулевая, особенно при росте объёма.
- **Уголовный** — практически неприменим: ст. 272 УК РФ требует преодоления защиты, а защиты нет технически, значит и преодолевать нечего.
- **Практический/репутационный — главный** — если сначала тихо работать в обход `robots.txt`, а потом «Кодекс» заметит, переговорная позиция для официального доступа (партнёрский API, как у Гаранта) станет хуже, чем если спросить сначала. Спросить сначала ничего не стоит и не ухудшает исход при отказе — только откладывает эту часть этапа 2.

Итог: технически можно, юридически риск невысокий, но неопределённый без ответа «Кодекса» или юриста компании. Само решение — управленческое, не техническое (см. `stage2-plan.md`, раздел «Порядок действий»).

## `base.garant.ru` — точный и надёжный, но плохо резолвится без готовой ссылки

Отдельные страницы читаются свободно, без логина, полный текст. Показывает `"(с изменениями и дополнениями от: <даты>)"` и, если отменён — явное `"Признан: <акт> утратившим силу с <дата>"`.

**Критическая оговорка: есть два разных типа URL, и только один надёжен.**
- `base.garant.ru/<ID>/` — «живая» карточка, статус отслеживается и обновляется.
- `garant.ru/products/ipo/prime/doc/<ID>/` — статичный снимок текста на момент первой публикации (лента ПРАЙМ), **не обновляется** при последующих изменениях статуса. На одном из тестов именно такая страница создала ложное впечатление, что документ ещё действует, хотя он был отменён.

**Резолвинг — нерешённая проблема.** Родной поиск (`base.garant.ru/search/`) уходит через DDoS-Guard в JS SPA (`ivo.garant.ru`), не скриптуется напрямую — пробовал повторить путь SPA вручную, бэкенд (легаси Python2.7/CherryPy) через раз отдаёт `400`/`411`. Sitemap существует (3333 файла по ~10 000 URL), но без метаданных — непригоден для сопоставления по реквизитам. Единственный проверенный способ найти нужный URL — веб-поиск (см. ниже про надёжность).

**Официальный платный API "Гарант Коннект"** (`api.garant.ru`) решает всё это чисто: `POST /v2/search` (резолвинг), `GET /v2/topic/$topic` (статус текстом), `GET /v2/redactions/$topic` (история со статусами и `changingDocuments[]`). Есть и MCP-обёртка (`mcp.garant.ru`) — можно подключить как MCP-коннектор в Claude Code. Но токен выдаётся только по запросу у обслуживающей организации, бесплатно — не более 7-дневного пробного доступа, не постоянный тариф.

## Веб-поиск как резолвер для Гаранта — эмпирическая надёжность

Проверено на 3 случаях: 2 успеха (правильный `base.garant.ru`, статус верный), 1 неудача (найден только `prime`-снимок без актуального статуса, при поиске строго по `base.garant.ru` — вообще ничего). **~65% на этой выборке**, и главный риск не в проценте, а в том, что «найдено что-то» не значит «найден надёжный источник статуса» — обязательно проверять, что URL именно `base.garant.ru/`, а не `garant.ru/products/ipo/prime/`.

## `bazanpa.ru` и `rulaws.ru` — свободно резолвятся, но статус может быть устаревшим

Оба бесплатны, без анти-бот защиты, поиск на простом GET.

- `bazanpa.ru`: `GET /search/?search_query=<текст>&search_root_category=zakonodatelstvo` — полнотекстовый, находит по цитате.
- `rulaws.ru`: `GET /findresult/?doc_num=<номер>&doc_establishment=<ID>` — точнее: отдельный фильтр по номеру и **готовая таблица ~80 федеральных ведомств с ID** (Минфин=1, ФНС=2, Минюст=20, Минприроды=38, Роснедра=43, Роспотребнадзор=34 и т.д. — см. форму на `rulaws.ru` для полного списка). Есть также чекбокс `is_making_change` — «Документы "о внесении изменений"» — потенциальный отдельный механизм для обратного поиска (какие документы изменили X), **не тестировался подробно**, стоит проверить отдельно.

**Оба показали одинаково устаревшие данные на одном и том же тесте** (пропустили правку от 26.04.2022, которую верно показали и `docs.cntd.ru`, и `base.garant.ru`) — похоже, используют общий бэкенд-фид с задержкой обновления. **Использовать только как резолвер кандидатов, статус с них не считать окончательным** без сверки с `docs.cntd.ru` или `ips.pravo.gov.ru`.

## `pravo-search.minjust.ru` — доступен, но не оправдывает трудозатрат

Реальная причина недоступности при первой проверке — **истёкший TLS-сертификат** сервера (`SEC_E_CERT_EXPIRED`), не геоблокировка. С обходом проверки сертификата сайт открывается, но поисковый движок — легаси Java/Struts-приложение (jQuery 1.7.2, эндпоинты `*.action`: `s.action`, `suggest.action`, `getDictionary.action`) с сессионным многошаговым взаимодействием, без простого одного GET-запроса для поиска. Тот же движок используют и другие госпорталы (общий white-label движок, судя по темам в CSS: sudrf, fssp и др.). Учитывая, что `docs.cntd.ru` уже даёт более полные и точные данные для той же категории документов — реверс-инжиниринг этого источника сейчас не оправдан.
