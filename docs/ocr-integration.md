# Интеграция с npa-ocr

Сканы без текстового слоя распознаёт отдельный проект
[npa-ocr](https://github.com/EduardIbatullin/npa-ocr). Он ничего не знает о
загрузчике: принимает PDF и возвращает DOCX.

## Когда нужен OCR

`fetch_document()` получает текст документа тремя способами, от лучшего к
дорогому:

1. **EBPI** — выверенный текст действующей редакции с таблицами (законы, указы,
   акты Правительства, высших судов, Банка России; см.
   [`ebpi-coverage.md`](ebpi-coverage.md)).
2. **Текстовый слой PDF** — если EBPI документ не покрывает, но PDF не скан
   (`text_layer_docx.py`); без структуры и таблиц.
3. **OCR** — только для сканов (хотя бы одна страница без текстового слоя).
   Автоматически из `fetch_document()` не вызывается: распознавание запускается
   из веб-приложения кнопкой «Распознать скан».

## Граница между проектами

npa-downloader не импортирует код npa-ocr и не ставит его в свой образ.
npa-ocr работает отдельным сервисом `ocr` в том же `docker-compose.yml`, в
общей сети compose (`http://ocr:8000`, без общих томов и без публикации порта).
Его образ `npa-ocr:latest` собирается в репозитории npa-ocr:

```bash
cd ../npa-ocr && docker build -t npa-ocr .
```

`src/npa_pipeline/ocr_jobs.py` (`OcrJobManager`) — HTTP-клиент сервиса:

| Действие | Запрос к npa-ocr |
|---|---|
| Отправить PDF | `POST /jobs` (multipart, `file`, `authority_name`) |
| Опросить ход | `GET /jobs/{id}` |
| Скачать результат | `GET /jobs/{id}/result` → `downloads/ocr/<stem>.docx` |
| Отменить | `POST /jobs/{id}/cancel` |

Адрес сервиса — `OCR_SERVICE_URL` (в compose — `http://ocr:8000`, без
compose — `http://localhost:8000`). Сервис выполняет одно задание
одновременно: занятый сервис отвечает `409`, клиент поднимает `JobBusyError`.
Недоступный сервис — `OcrServiceUnavailableError`, веб-API отвечает `503`, и
задание не создаётся.

Формат ответа сервиса описан в README npa-ocr («HTTP API»). При его изменении
`ocr_jobs.py` нужно обновить вручную: автоматической синхронизации между
проектами нет.

## Орган для восстановления шапки

Веб-приложение передаёт в npa-ocr наименование органа (`authority_name`): по
нему npa-ocr восстанавливает шапку документа и формулу должности подписанта,
повреждённые печатью или штампом. Для приказов министерств орган выводится из
полного названия документа («Приказ Министерства X от …» → «Министерство X»).

## Сервисы распознавания в compose

| Сервис | Образ | Назначение |
|---|---|---|
| `ocr` | `npa-ocr:latest` | HTTP API npa-ocr; таблицы — движком `vlm` (`NPA_OCR_TABLE_ENGINE=vlm`), обработка меток — через Ollama хоста (`OLLAMA_URL`) |
| `vlm-gate` | `npa-ocr:latest` | Шлюз vLLM: запускает контейнер `vlm` по первому запросу и останавливает после `VLM_IDLE_MIN` минут простоя; нужен сокет Docker |
| `vlm` | `vllm/vllm-openai` | DeepSeek-OCR; видеопамять задана явно, потому что GPU общая |

Если vLLM не запустился, npa-ocr распознаёт таблицы движком `tatr` на CPU.
Ollama работает вне этого compose; контейнеры обращаются к ней через
`host.docker.internal`.

Переменные `.env` для развёртывания: `WEB_PORT` (порт веб-приложения на хосте),
`MONITOR_HOSTNAME` (имя хоста на странице мониторинга), `VLM_IDLE_MIN`,
`VLM_HF_CACHE` (каталог кэша Hugging Face с весами DeepSeek-OCR).

## Порог текстового слоя

`ocr_jobs.count_scan_pages()` считает страницы без текстового слоя для подписи
в карточке НПА. Его порог `DEFAULT_MIN_PAGE_TEXT_CHARS = 20` повторяет порог
npa-ocr (константой, а не импортом). При изменении порога в npa-ocr его нужно
поправить и здесь, иначе счётчик в интерфейсе разойдётся с тем, что
распознаёт npa-ocr.
